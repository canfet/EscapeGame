# GPS 實境解謎闖關系統

用 GPS 定位打卡解鎖題目的實境解謎系統。學生**不用登入**，關主可以建立多個闖關專案，換地點時複製專案再改座標就能用。

- **前台／後台頁面**：GitHub Pages（免費、HTTPS、學生不會碰到 Google 登入）
- **API**：Google Apps Script
- **資料**：Google 試算表（所有紀錄都在這裡，可直接篩選、下載）
- **照片**：Google 雲端硬碟

完整設計請看 [DESIGN.md](DESIGN.md)。

## 部署步驟（約 15 分鐘）

### 步驟 1：建立試算表與 Apps Script

> 建議用**個人 Gmail** 帳號操作。學校帳號可能沒辦法把網頁應用程式開放給「所有人」。

1. 到 Google 雲端硬碟新增一份 **Google 試算表**，命名例如「實境解謎資料庫」。
2. 上方選單「擴充功能 → Apps Script」。
3. 把編輯器裡預設的 `程式碼.gs` 內容全部刪掉，貼上 `apps-script/Code.gs` 的內容，按 💾 儲存。
4. （選用）左側「專案設定 ⚙️」→ 勾選「在編輯器中顯示 appsscript.json」，把內容換成 `apps-script/appsscript.json`。至少確認時區是 `Asia/Taipei`。
5. 上方函式下拉選單選 `setup` → 按「執行」。
   - 第一次會要求授權：選你的帳號 →「進階」→「前往（不安全）」→「允許」。
   - 執行完成後，看下方「執行記錄」會顯示 **管理密碼**，請記下來。
6. 回到試算表重新整理，會看到 `Projects`、`Stages`、`Sessions`、`Submissions` 四張工作表和一個示範專案，上方也多了「🧩 實境解謎」選單。

### 步驟 2：部署成網頁應用程式（API）

1. Apps Script 右上角「部署 → 新增部署作業」。
2. 齒輪選「網頁應用程式」。
3. 設定：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
4. 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。

> ⚠️ 之後若修改 `Code.gs`，要到「部署 → 管理部署作業 → ✏️ 編輯 → 版本：新版本 → 部署」，網址不變，修改才會生效。

### 步驟 3：放到 GitHub Pages

1. 在 GitHub 建立一個新的 **Public** repository，例如 `gps-quest`。
2. 把整個資料夾的檔案上傳（可以直接在網頁上拖曳上傳）。
3. 編輯 `config.js`，把 `API_URL` 換成步驟 2 的網址（**fork 這個專案的人一定要改成自己的網址**，專案裡的 `config.js` 是原作者的；範本見 `config.example.js`）：
   ```js
   window.APP_CONFIG = {
     API_URL: 'https://script.google.com/macros/s/AKfy.../exec',
     SITE_NAME: 'GPS 實境解謎'
   };
   ```
4. repository 的「Settings → Pages」→ Source 選「Deploy from a branch」→ Branch 選 `main`、資料夾 `/ (root)` → Save。
5. 等 1～2 分鐘，網址會是：
   - 前台：`https://你的帳號.github.io/gps-quest/`
   - 後台：`https://你的帳號.github.io/gps-quest/admin.html`

> `apps-script/` 資料夾也會被公開，但裡面沒有任何密碼或答案，不影響安全。介意的話可以不上傳這個資料夾。

### 步驟 4：測試

1. 開後台，輸入管理密碼登入。
2. 示範專案的三關都設了通關碼 `1111`、`2222`、`3333`，人不在現場也能測完整流程。
3. 用「複製」建立你自己的專案，修改關卡座標後，狀態設 `hidden` 到現場實測。

## 日常使用

| 我想… | 怎麼做 |
|---|---|
| 換一個地點辦活動 | 後台「專案」→「複製」→ 到「關卡」改座標 |
| 決定這次玩哪個專案 | 給學生 `index.html?p=專案代碼` 的連結或 QR Code；或把專案設為「預設」 |
| 同一路線辦好幾場 | 產生連結時填「場次代碼」，紀錄會自動分開 |
| 看學生傳了什麼 | 後台「闖關紀錄」，或直接看試算表 `Submissions`；照片在雲端硬碟「GPS實境解謎_上傳照片」 |
| 直接改試算表 | 可以！改完約 30 秒內生效，或按選單「套用修改」 |
| 忘記管理密碼 | 試算表選單「🧩 實境解謎 → 顯示管理密碼」 |
| 換管理密碼 | 試算表選單「重設管理密碼」 |

## 關於 config.js 與安全

- `config.js` 裡的 `API_URL` **本來就是公開的**：網站是純靜態頁面，瀏覽器要呼叫後端，網址一定看得到。把它放進 GitHub 沒有問題，也沒辦法藏。
- **fork 或複製這個專案時，請務必把 `config.js` 的 `API_URL` 換成自己的**（參考 `config.example.js`，API_URL 留空）。沒改就會連到原作者的後端與試算表。
- 真正需要保護的是後端，系統已做了這些：
  - 所有後台功能（`admin*`）都必須帶**管理密碼**，由後端驗證，前端畫面藏起來不算數。管理密碼是 12 碼隨機字元，存在 Apps Script 的指令碼屬性，不在原始碼裡。
  - 猜密碼限制：15 分鐘內輸入錯誤 10 次，後台會暫時鎖定 15 分鐘（期間連正確密碼也不收，到期自動解除）。
  - 猜隊伍代碼限制：同一個專案 10 分鐘內輸入錯誤 20 次，暫時不能用代碼接續進度。
  - 請求頻率限制：同一支隊伍每分鐘最多 60 次操作；同一個專案每分鐘最多 300 次「開始闖關」，避免被灌垃圾資料或吃光 Apps Script 額度。以上數字可在 `Code.gs` 的 `RATE` 調整，一般活動不會碰到。
  - 玩家端只能做遊戲需要的動作（開始、打卡、作答、傳照片），試玩模式需要後台給的金鑰。
- 限制：Apps Script 拿不到使用者的 IP，所以頻率限制是以「隊伍／專案／後台」為單位，不是以人為單位。
- 管理密碼外洩時：試算表選單「🧩 實境解謎 → 重設管理密碼」。

## 防呆與自動備份

- **版本提醒**：前台和後端各有版本號。後端（Apps Script）版本過舊時，後台頂端會提示「請重新部署 Code.gs」；前台過舊時，玩家與管理者會看到「網站有新版本，請重新整理」。**更新 `Code.gs` 後記得「部署 → 管理部署作業 → 編輯 → 新版本」。**
- **活動進行中守門**：有隊伍正在闖關（6 小時內有操作）時，刪除或重排關卡、修改路線與隊伍名單、把專案改回準備中／已結束，都要輸入專案代碼才能繼續。刪除整個專案一律要輸入專案代碼。
- **開放前把關**：專案狀態改成「開放中」時會自動做活動前檢查；有嚴重錯誤（沒有關卡、座標缺失或不合理、隊伍或路線名稱重複…）會先退回「準備中」並列出原因，確認後才能強制開放。
- **輸入檢查**：緯度、經度超出範圍（常見於填反）直接擋下；座標離其他關卡超過 20 公里、抵達範圍小於 15 公尺會先確認；隊伍名單、路線名稱重複會擋下。
- **隊伍代碼**：新隊伍開始時會提示記下代碼，遊戲上方的代碼點一下可再次查看並複製；換手機或清除瀏覽器資料時，用它接回進度。
- **照片上傳**：選照片後自動壓縮到約 1.5 MB 以下，非圖片或超過 40 MB 的檔案會先提醒。
- **自動備份**：刪除專案、關卡、隊伍、圖鑑或清除試玩資料之前，會先把相關工作表複製成隱藏的「備份_時間_原因_表名」分頁（同一張表 10 分鐘內只備份一次，最多保留最新 24 張，超過 2 萬列的表不備份）。要找回：試算表選單「檢視 → 隱藏的工作表」顯示出來，再把資料複製回原本的工作表。

## 速度與效能

- 後端每個動作的處理時間（毫秒）會放在回應裡：在瀏覽器按 F12 → Console，會看到 `[api] 動作：後端 xxx ms／整體 xxx ms`。「後端」是 Apps Script 實際處理時間，「整體」包含網路與 Google 轉址；整體遠大於後端，就是網路或冷啟動（閒置後第一次呼叫）造成的。
- 同一個請求裡，同一張工作表只會讀一次；取得寫入鎖之後會重新讀，確保不會讀到舊資料。
- 後台登入、儲存圖鑑後，專案與圖鑑清單同時讀取；活動中危險操作前的「有沒有隊伍在玩」改用只讀隊伍表的輕量查詢。
- 上傳圖片時，圖片資料夾只設定一次「知道連結的人可檢視」，不再每張圖各自設定分享（省 1～2 秒）。若換圖後發現圖片打不開，請到雲端硬碟 `GPS實境解謎_上傳照片/<專案>/_images` 確認資料夾分享是「知道連結的任何人」。

## 活動前負載演練

很多隊伍同時作答時，寫入會排隊（Apps Script 的寫入鎖）。正式活動前可以先跑一次演練：

```
node tools/loadtest.js <API_URL> <管理密碼> <專案代碼> [隊伍數=30] [秒數=30]
```

- 需要 Node 18 以上。全部使用「試玩隊伍」，不進排行榜，結束後自動清除（清除前會自動備份）。
- 會列出成功率、排隊逾時（BUSY）次數，以及回應時間的中位數與 p95。演練腳本**不會自動重試**，所以 BUSY 比真實玩家遇到的更多；玩家端會自動重試最多 4 次。
- 專案若設了「預設隊伍名單」，試玩隊伍名稱會被擋，請用沒有名單的測試專案。
- 請在沒有正式活動時跑，並避免連續跑很多次（會消耗 Apps Script 每日額度）。
- 後端已縮短寫入鎖的占用時間：鎖內只做「讀進度、判斷、寫回進度」；寫作答紀錄、整理回傳畫面資料、上傳照片到雲端硬碟都在解鎖之後。

## 常見問題

**前台顯示「伺服器回應格式錯誤」**
Apps Script 部署時「誰可以存取」不是「所有人」，或修改程式後沒有部署新版本。

**定位一直說太遠／誤差太大**
請學生到空曠處，手機開啟「精確位置」；後台可以把該關半徑放大，或專案的「可接受定位誤差」調高，或改用現場通關碼。

**iPhone 沒有跳出定位詢問**
設定 → 隱私權與安全性 → 定位服務 → Safari 網站 → 「使用 App 期間」，然後重新整理頁面。

**學校網路打不開**
少數學校防火牆會擋 `github.io` 或 `script.google.com`，請活動前用學生裝置和學校網路測試，必要時改用手機網路。

**地圖沒有顯示**
地圖使用 OpenStreetMap，若網路擋住地圖圖磚，關卡功能仍可正常使用（距離與打卡不受影響）。
